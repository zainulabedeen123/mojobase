One project, a whole backend

Everything your app needs, already wired together

No stitching services together. Each project ships with the pieces below, sharing one auth model and one database.

Postgres database

A dedicated Postgres for every project, not a shared schema. Tables become a typed REST API instantly, and you can connect directly with a connection string from psql, Prisma or Drizzle.

  • Row-level security
  • pgvector
  • SQL editor and migrations
create table posts (
  id uuid primary key,
  user_id uuid default auth.uid(),
  title text not null
);
alter table posts
  enable row level security;

Authentication

Email and password, OAuth providers, email verification and password reset. Sessions flow into Postgres policies through auth.uid().

Storage

Buckets for images, video and documents, public or private, with uploads straight from the browser.

Edge functions

Server-side TypeScript on Deno. Deploy from your agent or the dashboard, invoke from the SDK or plain HTTP, run on a schedule.

Realtime

Channels, presence and database-triggered events over WebSockets, protected by the same policies as your data.

Model gateway

Chat, embeddings and image generation behind one API. Bring your OpenRouter key and switch between hundreds of models.

Payments

Stripe and Razorpay checkout, subscriptions and webhooks, with your own provider keys.

A dashboard for everything

Edit tables, manage users, browse storage, read logs and run SQL. Your agent builds; you always see exactly what it built.

MCP setup guide 
# one command, then ask: "create a Mojobase project for this app"
claude mcp add --transport http mojobase https://mojobase.dev/mcp \
  --header "Authorization: Bearer mbp_your_token"
// ~/.cursor/mcp.json
{
  "mcpServers": {
    "mojobase": {
      "url": "https://mojobase.dev/mcp",
      "headers": { "Authorization": "Bearer mbp_your_token" }
    }
  }
}
// .vscode/mcp.json
{
  "servers": {
    "mojobase": {
      "type": "http",
      "url": "https://mojobase.dev/mcp",
      "headers": { "Authorization": "Bearer mbp_your_token" }
    }
  }
}
import { createClient } from '@mojobase/sdk';

const mojobase = createClient({
  baseUrl: 'https://your-project.mojobase.dev',
  anonKey: process.env.MOJOBASE_ANON_KEY,
});

// Row-level security decides what each user sees
const { data, error } = await mojobase.database
  .from('posts')
  .select('*')
  .order('created_at', { ascending: false });
await mojobase.auth.signUp({ email, password, name });

await mojobase.auth.signInWithPassword({ email, password });

// Restore the session on page load
const { data } = await mojobase.auth.getCurrentUser();

// Upload a file as the signed-in user
await mojobase.storage
  .from('avatars')
  .upload(`${data.user.id}/avatar.png`, file);
# A real connection string for every project. TLS required.
psql "postgresql://mojobase:••••@db.mojobase.dev:15400/insforge?sslmode=require"

# Prisma
DATABASE_URL="postgresql://mojobase:••••@db.mojobase.dev:15400/insforge?sslmode=require"
npx prisma migrate deploy

# Drizzle
export const db = drizzle(process.env.DATABASE_URL);
# Every table is an API
curl 'https://your-project.mojobase.dev/api/database/records/posts?select=*' \
  -H "Authorization: Bearer $MOJOBASE_ANON_KEY"

# Call an edge function
curl -X POST 'https://your-project.mojobase.dev/functions/checkout' \
  -H 'Content-Type: application/json' \
  -d '{"cart": "c_123"}'

Quickstart

Isolated and secure by default

Your project is yours alone

The safe path is the default path, so what your agent ships is what you would have written yourself.

A database per project

Each project runs its own Postgres, API and functions runtime. No shared tables, no noisy neighbours in your schema.

Encrypted connections

Direct database connections require TLS, and the connection role owns your tables without server superuser rights.

Row-level security first

The integration prompt and docs put policies on every table the client touches, keyed to the signed-in user.

Backups you can restore

Automatic nightly database backups plus manual snapshots, restorable from the dashboard in a click.

Keys that stay server-side

A browser-safe anon key for clients and a separate admin key for servers, clearly labelled everywhere they appear.
